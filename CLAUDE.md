# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`currency-mobile` is a Kotlin Multiplatform + Compose Multiplatform mobile app (Kotlin 2.1.0, Compose
Multiplatform 1.7.0) targeting Android and iOS, converting between currencies using live rates and the
full currency list fetched from the [currency-calculator](https://github.com/b-scharbau/currency-calculator)
API (`currency.bscharbau.com`). Single `composeApp` module; namespace/applicationId
`com.bscharbau.currencymobile`. Design mirrors that backend's Angular frontend / bscharbau.com, and the
UI is localized the same way bscharbau.com is (English/German/Japanese).

See `README.md` for the full architectural rationale (persistence caching philosophy, locale-aware
amount formatting, dark mode, layout, splash screen, icon generation) — this file covers what's needed
to orient quickly and work in the repo; the README covers *why* things are built the way they are.

## Commands

Use the Gradle wrapper (`./gradlew`); no local Gradle install required. Requires JDK 17+ and an Android
SDK (compileSdk 35, minSdk 24) — point `local.properties` at it (`sdk.dir=/path/to/sdk`).

- Build the Android debug APK: `./gradlew :composeApp:assembleDebug`
- Run the shared + Android unit tests: `./gradlew :composeApp:testDebugUnitTest`
- Both together (what CI runs): `./gradlew :composeApp:assembleDebug :composeApp:testDebugUnitTest --stacktrace`
- Run a single test class: `./gradlew :composeApp:testDebugUnitTest --tests "AmountFormattingTest"`

**iOS cannot be built or tested on Linux** — Kotlin/Native only compiles iOS targets (`iosX64`,
`iosArm64`, `iosSimulatorArm64`) on macOS with Xcode. The target is declared and `MainViewController.kt`
is real code, but unverified in this dev environment; don't claim iOS changes are "tested" without a Mac.

## Architecture

- **`composeApp/src/commonMain`** — shared code. `App.kt` (root composable: state, effects, the
  portrait/landscape layout switch) lives at the package root; the rest of the UI
  (`HeroContent.kt`, `CurrencySelection.kt`, `ConversionFields.kt`, `CurrencyPicker.kt`,
  `SwapButton.kt`) is under the `ui` subpackage, one composable per file. Also: `CurrencyApi.kt`
  (Ktor), `NetworkRetry.kt`, `CurrencyRepository.kt`, `CurrencyConverter.kt`, `AmountFormatting.kt`,
  `Theme.kt`, `SignalDivider.kt`, `db/DatabaseDriverFactory.kt` (`expect`).
- **`composeApp/src/commonMain/composeResources`** — `font/` (bundled TTFs) and
  `values{,-de,-ja}/strings.xml` (localized UI text via Compose's own resource-qualifier system,
  read with `stringResource(Res.string.xxx)`).
- **`composeApp/src/commonMain/sqldelight`** — `Currency.sq`/`Rate.sq`, SQLDelight generates the
  typed `AppDatabase` API (package `com.bscharbau.currencymobile.db`).
- **`composeApp/src/androidMain`** — `MainActivity.kt`, `actual DatabaseDriverFactory`
  (`AndroidSqliteDriver`), launcher icon resources (`res/mipmap-*`, generated by
  `graphics/gen_icons.py`), splash/theme resources (`res/values{,-night}/{colors,themes}.xml`).
- **`composeApp/src/iosMain`** — `MainViewController.kt`, `actual DatabaseDriverFactory`
  (`NativeSqliteDriver`).
- **`composeApp/src/commonTest`** — unit tests using Ktor's `MockEngine` (no live network calls).
- **`composeApp/src/androidUnitTest`** — `CurrencyRepositoryTest.kt`, against a real in-memory
  SQLite database via SQLDelight's JDBC driver (Android local unit tests run on a plain JVM with no
  real `AndroidSqliteDriver` available).

Key behaviors worth knowing before touching related code (details/rationale in `README.md`):

- **Caching**: rates are cached per-day (today's cached value skips the network entirely; a failed
  refresh falls back to stale data rather than erroring); the currency list is cached once and never
  auto-refreshed.
- **Amount input**: accepts either `.` or `,` as the decimal point (Android's decimal keypad offers
  both regardless of locale); *display* grouping/decimal-glyph is locale-aware via
  `ThousandsVisualTransformation`.
- **Localization**: `stringResource()` is `@Composable` and can't be called from the `LaunchedEffect`
  coroutines that catch network exceptions — error state stores the raw exception detail and defers
  building the localized message to display time.
- **Dark mode**: `BrandColors.xxx` properties are `@Composable` getters over a `CompositionLocal`
  palette, so most call sites don't need to be theme-aware explicitly — the one exception is
  `SignalDivider`'s `Canvas` draw lambda, which isn't a composable context.

## Testing

Three levels, mirroring the backend's test pyramid: `commonTest` (pure logic — conversion math,
API parsing, retry policy, amount formatting/offset-mapping — no Spring-equivalent DI, no network),
`androidUnitTest` (repository behavior against a real SQLite JDBC database), and manual emulator
verification for anything visual (layout, dark mode, splash screen, locale rendering) — screenshots
belong in the PR description or a scratch dir, not committed, except `screenshots/portrait.png` /
`screenshots/landscape.png` which the README embeds deliberately.

**Locale-switching gotcha when verifying UI text on an emulator**: a live `adb shell settings put
system system_locales <locale>` change or a bare app process restart is **not** enough — Compose
Resources resolves the locale through Android's full `Configuration`, and `system_server` doesn't
reliably re-propagate a changed locale to freshly-launched apps without a full `adb reboot`. Also
watch for stale per-app locale overrides from `cmd locale set-app-locales` polluting the resolved
`LocaleList` (check via `dumpsys activity <package> | grep mCurrentConfig`) — clear with
`cmd locale set-app-locales <package> --locales emptyList` if a previous test left one behind.

See the README's "Running on an emulator" section for KVM/AVD setup from scratch.
